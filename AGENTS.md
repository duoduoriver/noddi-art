# TanStack Start on Cloudflare Workers

## Local facts

- Use `pnpm`; do not add npm or yarn lockfiles. Useful checks are `pnpm check`, `pnpm test`, and `pnpm build`; start locally with `pnpm dev`.
- Routes are file-based under `src/routes/`; `src/routeTree.gen.ts` is generated and must not be edited. Server functions live in `src/api/` and protected paths use the existing auth/admin middleware.
- Keep application schema changes in `src/db/app.schema.ts`; `src/db/auth.schema.ts` is generated by `pnpm auth:schema:generate`.
- This runs on Workers: avoid Node.js-only APIs. Reuse the existing provider and Wrangler-binding paths rather than creating parallel auth, database, payment, or deployment flows.

## Safety and completion

- For environment changes, consult `src/env/client.ts`, `src/env/server.ts`, and `.env.example`; do not read `.env`, `.env.local`, Wrangler secrets, or production data unless the user explicitly asks.
- For schema changes use `pnpm db:generate` and `pnpm db:migrate:local`, and record rollback notes. Do not run remote D1 migrations/writes or deploy without explicit approval.
- For a release, check the repository and run `pnpm build` before an approved `pnpm deploy`. Performance audits are opt-in: use `web-perf` with Chrome DevTools MCP, not ego-browser; if trace tools are unavailable, ask to configure them.
- Run only validation appropriate to the requested change and report what ran, what did not, and remaining risks.

## Local skills

Use `.agents/skills/tanstack-quick-start/` only for first-pass starter customization and `.agents/skills/tanstack-page-builder/` only for new marketing/content pages. Read the selected skill before using it.

For module-specific work, consult the relevant `docs/` page rather than a full documentation tour. `pnpm lint` writes fixes; inspect the package script before choosing a read-only check. Client `VITE_` values are build-time; server configuration uses Worker bindings.
